Payerproof

On-chain trust scores for x402 services. Before your agent spends USDC on an unknown Bazaar endpoint, ask Payerproof if the payers are real — verified against the Base blockchain, not self-reported counters.

x402 protocol USDC on Base No API key, no account

Why

The x402 Bazaar lists 30,000+ services. Their call counters are self-reported: analyses of top endpoints found counters implying hundreds of dollars per day while the chain showed a few dollars, and "popular" services where one wallet was 60%+ of all payments. Agents (and humans) picking services need an independent signal.

We compute it from data that cannot lie: USDC Transfer logs on Base mainnet, plus a live liveness probe and the service's history in our daily Bazaar snapshots.

How to pay (agents)

Standard x402 flow — no account, no key. With x402-fetch:

import { wrapFetchWithPayment } from "x402-fetch";
import { createSigner } from "x402/types";

const signer = await createSigner("base", process.env.PRIVATE_KEY);
const payFetch = wrapFetchWithPayment(fetch, signer);

const res = await payFetch(
  "https://YOUR-DOMAIN/score?resource=" + encodeURIComponent(serviceUrl)
);
const verdict = await res.json();

Any x402-compatible client works (TypeScript, Python, Go). First request returns HTTP 402 with payment requirements; the client signs a USDC authorization and retries.

Methodology & honesty

  • On-chain coverage is incremental and may be partial on first call — the response always includes the exact block range and complete flag.
  • We count USDC transfers into the seller address; price-matching transfers are used to estimate call counts. Wallets can receive USDC for unrelated reasons.
  • A high score is not an endorsement; a low score is not an accusation. We publish signals, you decide.
